The PR correctly does not claim to satisfy Act 19's three-distinct-transient-failure threshold; issue `4Ux4sxiHjpXqSi9T9d2suq-alabama` remains legally open. This review does not close or amend it.

## Objections and limits

1. **Log/worktree capture errors are swallowed.** `antonina agent log --lines 80 ... || :` ignores a nonzero result; `git status --short ... || :` leaves an empty file on error, indistinguishable from a clean worktree. The existing appointment smoke's mocked `antonina` has no `agent log` case, so that command returns its “unexpected mocked command” error, yet the script proceeds and the test passes without asserting actual log-tail contents. Thus the test demonstrates the current gap: a replacement can proceed without a captured old log, and an unreadable Git status can look clean. The raw status and HEAD fallback are preserved, but completeness is not fail-closed.
2. **Unreadable status has a TOCTOU window.** The `ensure` path treats any failed `agent status` command as not-live and records synthetic `unreadable`; it does not re-query immediately before replacing. `resolve` deliberately skips the appointment lock. If the first status read fails transiently while the old agent is still running, a concurrent resolver can obtain and return the old live ID while `ensure` proceeds to create/register a new agent. If instructions are stale, `appointments.sh` then invokes `policy-sync.sh` on the shared worktree after the snapshot. The evidence is useful for diagnosis, but the code does not establish that an unreadable appointee has stopped or prevent duplicate live sessions/worktree use.
3. **Snapshot and append-only index are not one atomic transaction.** The per-ID evidence directory is atomically moved into place before appending `terminal-events.jsonl`. A crash or append error in that interval leaves `event.json` present but the index row absent. A retry sees the directory and returns success immediately without validating or repairing the index. The event file still preserves the primary snapshot; the convenience index can nevertheless be incomplete. The official caller serializes normal appends under the appointment lock, but the helper itself has no lock if invoked directly.
4. **Bounded by line count, not bytes or time.** `--lines 80` does not cap individual line size; `git status --short` output is also unbounded. Neither capture has a timeout. A very large log/status can consume substantial private-state storage or hold the appointment lock for an unbounded time. The full suite has no large-log, timeout, interrupted-index, or concurrent-resolver test. Its idempotence check repeats `ensure` for an already-live current ID; it does not call the recorder twice for the same departed ID.
5. **Privacy mode is scoped.** The evidence helper uses `umask 077` before creating its temp directory/files, and the intended caller sets the same umask before invoking it; thus the new evidence directory/files are private in the normal path. The existing `appointments` parent is mode `0755` on this host because `appointments.sh` creates it before setting umask; files are mode `0600`. The smoke test does not assert permissions, and the helper alone would create `terminal-evidence/` under the caller's inherited umask if invoked outside the wrapper.

The first correction (preserve status/finished time/retry-safety before replacing) is exercised successfully. The fail-closed guarantee is narrower than the docs suggest: status parsing and core directory publication failures stop replacement, but log and Git-status acquisition failures are tolerated without explicit structured unavailable markers. No claim is made here that the separate Act 19 reset-threshold contradiction is solved.
