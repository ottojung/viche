## What was wrong

The deployed PnP path generated candidates and ran Lean checks on an external
host through the Marceline relay (`marceline-request`, `relay.mjs`, worker
handlers, remote checkers and async submission). That crosses the current
host assignment: Viche/PnP agent execution and proof/check subprocesses are
permitted only on billy-dev. Existing generated candidates and historical
receipts must not be relabeled or promoted to local-verified status.

## What this patch does

- Adds `missions/pnp/host_boundary.py` as the single unconditional refusal
  contract (`remote_transport_disabled`, exit 9). No env var, config, installed
  executable or fallback can relax it. GitHub-hosted Actions CI is unaffected.
- Keeps local, bounded useful work: local lower-bound candidate generation,
  promise-family/Batch generation, local plugin generation and local sibling
  indexing. Generated bytes are candidate source, never compiler receipts.
- Routes the only current Lean verification through the managed compiler from
  an exact active bound workspace (`checklocal.py`;
  `PYTHONPATH=... python3 -m missions.pnp.compile -- lake env lean FILE`).
- Converts every relay transport entry point to a fail-closed stub that spawns
  nothing: `marceline-request`, `relay.mjs`, `pnp-remote-check.py`, the three
  worker handlers, `refresh-cache.py`, `worker-lock.py`, `service-run`,
  `cache-service-run`, `install.sh`, `install-worker.sh`, and
  `lbcert/patch_relay.py` (which could have re-injected a worker into the relay).
- Disables async submission/polling; reconciliation is read-only and preserves
  legacy pending rows and their request ids without contacting a transport or
  converting a remote claim into a local/kernel verdict.
- Updates playbooks, tools inventory and docs so no guidance instructs an
  agent to use out-of-host compute; updates the affected regression tests.
